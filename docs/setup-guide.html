Section 1

What This Project Does

This project turns your WhatsApp Business phone number into a live AI voice agent. When someone calls your number via WhatsApp, the call is automatically answered by an AI assistant that listens, understands, and responds in real time — just like a phone conversation with a human agent.

No caller-side app installation is required. Any WhatsApp user can call your business number and immediately speak to the AI.

CapabilityTechnologyNotes
Receive WhatsApp callsMeta WhatsApp Business APIWebhook-driven SDP/WebRTC handshake
Hear the caller's voiceDeepgram STTNova-2 model, real-time streaming
Understand and respondOpenRouter LLMAny model — GPT-4o, Claude, Llama, etc.
Speak the responseDeepgram TTS AuraLow-latency neural voice synthesis
Detect speech boundariesSilero VADRuns locally, no extra API key needed
Section 2

How a Call Works — User Perspective

1
Caller dials your WhatsApp Business number
Any WhatsApp user opens the app, finds your number, and taps the call button. No special setup on their side.
2
WhatsApp notifies your server
Meta's infrastructure sends a webhook POST to your server containing the call's SDP offer (WebRTC session description).
3
Your server answers the call
The bot generates an SDP answer and calls Meta's Graph API to pre-accept the call within milliseconds.
4
WebRTC audio channel opens
A live, encrypted audio stream is established between the caller's device and your server using the WebRTC protocol.
5
AI pipeline activates
The Pipecat pipeline processes audio in real time: VAD detects speech → Deepgram transcribes → LLM generates response → Deepgram synthesises voice → caller hears response.
6
Conversation continues until caller hangs up
The pipeline loops continuously, maintaining full conversation context across all turns until the caller disconnects.
✓

From the caller's point of view: They simply dial a WhatsApp number. The AI answers in under 2 seconds, speaks naturally, and understands everything they say. There is no hold music, no IVR menu, and no app to install.

Section 7

Step 3 — Collect Your API Keys

7a · OpenRouter

LLM API Key

  1. Go to openrouter.ai and sign in
  2. Navigate to Keys → Create Key
  3. Copy the key — it starts with sk-or-v1-
  4. Choose a model at openrouter.ai/models

The default model is arcee-ai/trinity-large-preview:free (a free model). Any model on OpenRouter works.

7b · Deepgram

Speech API Key

  1. Go to console.deepgram.com and sign in
  2. Navigate to API Keys → Create a New API Key
  3. Give it a name and click Create Key
  4. Copy the key — it is shown only once

One Deepgram key handles both speech-to-text and text-to-speech.

7c · WhatsApp / Meta

Three values from Meta

See Section 8 for the full walkthrough. You need:

VariableWhere to find it
WHATSAPP_TOKENMeta Console → WhatsApp → API Setup → Access Token
WHATSAPP_PHONE_NUMBER_IDMeta Console → WhatsApp → API Setup → Phone Number ID
WHATSAPP_APP_SECRETMeta Console → App Settings → Basic → App Secret
7d · Webhook Token

Verification Token (you choose this)

This is a string you invent yourself. It can be any word or phrase — for example my-secret-token-123. You will enter the same string in your .env file and in the Meta webhook settings.

Section 8 — Most Important

Step 4 — Configure Meta Developer Console

⚠

This is the most critical configuration step. Mistakes here are the most common cause of the bot not working. Follow each sub-step exactly.

8a

Create a Meta App (if you don't have one)

  1. Go to developers.facebook.com
  2. Click My Apps → Create App
  3. Select Other as the use case → click Next
  4. Select Business as the app type → click Next
  5. Enter an app name (e.g., "My AI Voice Bot") → click Create App
8b

Add WhatsApp to Your App

  1. In your app dashboard, find Add Products to Your App
  2. Find WhatsApp and click Set Up
8c

Get Your Access Token and Phone Number ID

  1. In the left sidebar, click WhatsApp → API Setup
  2. Under Step 1, note your Phone Number ID — copy it
  3. Under Step 2, click Generate access token — copy it
⚠

This access token expires in approximately 2 hours. For production, create a permanent System User token. See: developers.facebook.com/blog/post/2022/12/05/auth-tokens/

8d

Get Your App Secret

  1. In the left sidebar, click Settings → Basic
  2. Find the App Secret field — click Show
  3. Enter your Facebook password when prompted
  4. Copy the App Secret
8e — Critical

Enable Voice Calls on Your Phone Number

WhatsApp voice calling for businesses is a separate feature that must be explicitly enabled.

  1. In the left sidebar, click WhatsApp → Configuration
  2. Find Phone Numbers → click Manage Phone Numbers
  3. Select your phone number
  4. Click the Calls tab
  5. Toggle Allow voice calls to ON
  6. Click Save
8f

Set Up the Webhook

  1. Still on WhatsApp → Configuration
  2. Scroll to the Webhook section → click Edit
  3. Set Callback URL to your server address + /whatsapp
    (During local testing use your ngrok URL — set this after Step 11)
  4. Set Verify Token to the string you chose in Step 7d
  5. Click Verify and Save
8g — Critical

Subscribe to the calls Webhook Field

✕

Without this step, WhatsApp will NOT send call events to your bot. The bot will appear to run but will never answer calls.

  1. On WhatsApp → Configuration, scroll to Webhook Fields
  2. Find calls in the list
  3. Click the toggle next to calls to enable it — it should turn blue

Checkpoint — Before Continuing

  • WhatsApp added to your Meta app
  • Access token copied to clipboard
  • Phone Number ID copied to clipboard
  • App Secret copied to clipboard
  • Voice calls enabled on your phone number
  • Webhook calls field subscribed (toggled on)
Section 9

Step 5 — Set Up Your Environment File

cp env.example .env

Open .env in a text editor and fill in every value:

# ── LLM via OpenRouter ───────────────────────────────────
OPENROUTER_API_KEY=sk-or-v1-YOUR_KEY_HERE
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
OPENROUTER_LLM_MODEL=arcee-ai/trinity-large-preview:free

# ── Speech (Deepgram) ────────────────────────────────────
DEEPGRAM_API_KEY=YOUR_DEEPGRAM_KEY_HERE

# ── WhatsApp / Meta ──────────────────────────────────────
WHATSAPP_TOKEN=YOUR_ACCESS_TOKEN_FROM_META
WHATSAPP_PHONE_NUMBER_ID=YOUR_PHONE_NUMBER_ID_FROM_META
WHATSAPP_APP_SECRET=YOUR_APP_SECRET_FROM_META

# ── Local development only ───────────────────────────────
WHATSAPP_WEBHOOK_VERIFICATION_TOKEN=my-secret-token-123
✕

Never commit .env to version control. It contains sensitive credentials. It is already listed in .gitignore.

Section 11

Step 7 — Expose to the Internet with ngrok

WhatsApp needs to reach your local server from the internet. ngrok creates a secure HTTPS tunnel from a public URL to your localhost:7860.

Open a new terminal window (keep the bot running in the first) and run:

ngrok http 7860

ngrok displays:

Forwarding   https://abc123.ngrok-free.app -> http://localhost:7860

Your webhook URL is this URL with /whatsapp appended:

https://abc123.ngrok-free.app/whatsapp
✓

If you have a paid ngrok plan with a static domain:
ngrok http --domain=your-domain.ngrok.io 7860

Section 12

Step 8 — Connect Meta Webhook

  1. Go to Meta Developer Console → Your App → WhatsApp → Configuration
  2. In the Webhook section, click Edit
  3. Set Callback URL to: 
    https://YOUR-NGROK-URL.ngrok-free.app/whatsapp
  4. Set Verify Token to the same value as WHATSAPP_WEBHOOK_VERIFICATION_TOKEN in your .env
  5. Click Verify and Save

During verification, Meta sends a GET request to your server. You should see in your bot terminal:

INFO   Webhook verification successful

If verification fails, check:

  • Your ngrok tunnel is running
  • The Verify Token matches exactly (it is case-sensitive)
  • The URL ends with /whatsapp (not /whatsapp/)

Section 14

Step 10 — Deploy to Production (Pipecat Cloud)

Local development with ngrok is temporary — the URL changes each time you restart ngrok. For a permanent, always-on deployment, use Pipecat Cloud.

14a. Prerequisites

  • A Docker Hub account (free at hub.docker.com)
  • Docker installed on your machine
  • A Pipecat Cloud account (pipecat.daily.co)

14b. Update pcc-deploy.toml

Open pcc-deploy.toml and replace YOUR_DOCKERHUB_USERNAME with your actual Docker Hub username:

agent_name = "whatsapp-voice-agent"
image = "yourdockerhubusername/whatsapp-voice-agent:0.1"
secret_set = "whatsapp-secrets"

[scaling]
min_agents = 1

14c. Deploy

# 1. Log in to Pipecat Cloud
uv run pcc auth login

# 2. Upload your secrets securely
uv run pcc secrets set whatsapp-secrets --file .env

# 3. Build and push Docker image
uv run pcc docker build-push

# 4. Deploy the agent
uv run pcc deploy

14d. Update Meta Webhook for Production

After deployment, your permanent webhook URL follows this pattern:

https://api.pipecat.daily.co/v1/public/webhooks/YOUR_ORG_NAME/whatsapp-voice-agent/whatsapp
  1. Go to Meta Developer Console → WhatsApp → Configuration → Webhook
  2. Update Callback URL to the Pipecat Cloud URL
  3. Update Verify Token to your Pipecat Cloud public API key
    (found in your Pipecat Cloud dashboard — this is different from your local token)
  4. Click Verify and Save
⚠

The production Verify Token must be your Pipecat Cloud public API key, not the string you used for local testing.

Section 15

Customising the Agent

Change the AI's Personality

Edit bot_prompt.py:

BOT_SYSTEM_PROMPT = """
You are a helpful customer service agent for Acme Corp.
You assist customers with order tracking and product questions.
Keep responses to 1-2 sentences. Always be professional and polite.
"""

Change the LLM Model

Update OPENROUTER_LLM_MODEL in your .env file:

# Examples — browse models at openrouter.ai/models
OPENROUTER_LLM_MODEL=openai/gpt-4o-mini
OPENROUTER_LLM_MODEL=anthropic/claude-3-haiku
OPENROUTER_LLM_MODEL=meta-llama/llama-3.1-8b-instruct:free

Change the Voice

Edit the voice setting in bot.py:

tts = DeepgramTTSService(
    api_key=os.environ["DEEPGRAM_API_KEY"],
    settings=DeepgramTTSService.Settings(voice="aura-2-zeus-en"),  # male voice
)

Available voices: aura-2-helena-en (female), aura-2-zeus-en (male), aura-2-luna-en (female). Full list at developers.deepgram.com/docs/tts-models.

Section 17

Troubleshooting

Webhook verification fails (403 or "token mismatch")
Cause: The Verify Token in Meta does not match WHATSAPP_WEBHOOK_VERIFICATION_TOKEN in .env.

Fix: Make sure both values are identical — this comparison is case-sensitive. Restart the bot after changing .env.
Bot does not answer calls (no logs when calling)
Cause: The calls webhook field is not subscribed in Meta.

Fix: Meta Developer Console → WhatsApp → Configuration → Webhook Fields → find calls → toggle it on.
"Error validating access token" in logs
Cause: WHATSAPP_TOKEN expires after approximately 2 hours.

Fix: Meta Console → WhatsApp → API Setup → generate a new token → update .env → restart the bot. For production, use a permanent System User token.
Call connects but no audio (silent call)
Cause: Usually a missing or invalid DEEPGRAM_API_KEY.

Fix: Verify the key is correct in .env. Test it at console.deepgram.com.
SSLCertVerificationError connecting to graph.facebook.com
Cause: macOS Python does not use system certificates by default.

Fix: Run this once:
open "/Applications/Python 3.12/Install Certificates.command"
POST /whatsapp returns 404
Cause: The bot was started without the --whatsapp flag.

Fix: Always use uv run bot.py — the required flags are now injected automatically. Do not pass conflicting transport flags manually.
Bot crashes immediately after answering
Cause: A missing or mistyped environment variable.

Fix: Check your .env file for all 7 required variables. Look for Starting bot | LLM model=NOT SET in logs to identify which variable is missing.
Call connects but bot seems unresponsive
Cause: OpenRouter model may be slow or the selected model is unavailable.

Fix: Try switching to a faster model like openai/gpt-4o-mini or meta-llama/llama-3.1-8b-instruct:free.
